# requirement-0008

## Summary

Provide an operation-aware fluent form factory API so developers can define default fields and per-operation field differences (READ/ADD/UPDATE/DELETE) with minimal boilerplate.

## Example

```java
Crud<User> userCrud = Crud.of(User.class)
        .form(AutoGeneratedFormFactory.of(User.class)
                .fields( // already exists
                        Field.of(User::getName, User::setName).caption("The name"),
                        Field.of(User::getEmail, User::setEmail).caption("The email"),
                        Field.of(User::getGroups, User::setGroups).caption("The groups"))
                .fieldsFor(CrudOperation.DELETE, // new: sets the fields only for this operation
                        Field.of(User::getName, User::setName).caption("The name"),
                        Field.of(User::getEmail, User::setEmail).caption("The email"))
                .additionalFieldsFor(CrudOperation.ADD, // new: adds as opposed to set or replace (add to what is already there)
                        Field.of(User::getPassword, User::setPassword).caption("The password")))
        .build();
```

## Behavior

- The API must support defining a default set of fields used by all operations unless overridden.
- The API must support replacing field sets per operation.
- The API must support adding extra fields per operation without redefining the full set.
- Method-reference (`Field.of(User::getName...`) and property-based (`Field.of("name"...`) field definitions MUST BOTH BE SUPPORTED.
